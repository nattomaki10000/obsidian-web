# obsidian-web 静的版 → Cloudflare Pages + Workers KV 版

異なる端末(PC・スマホ・タブレット)で**同じvault**を使うための改造版です。完全無料の範囲で動くように作ってあります。

- フロント(ランチャー・shim)と、KVを読み書きするAPI(`_worker.js`)を **Cloudflare Pages** で動かします
- vaultの中身は **Workers KV** に保存します
- 入るにはパスワードが必要です(パスワードは Pages の Secret に置きます)
- Obsidian本体(`obsidian.asar` / モバイル版`public`のzip)は、これまで通り**各端末で読み込む**方式です(サイトには置きません)

## アップロードするもの

`obsidian-web-kv-pages.zip` を Pages の「アップロード」にそのまま入れます(zipの**直下**に `_worker.js` などが並んでいます)。

| ファイル | 役割 |
|---|---|
| `_worker.js` | 認証 + KV API。**すべてのリクエスト**がここを通り、ログインしていないとログイン画面以外は返しません |
| `login.html` | ログイン画面 |
| `kv-fs.js` | KVをフォルダのように見せる層。**まとめ書き込み**・端末内キャッシュ・オフライン起動もここ |
| `index.html` `launcher.js` `sw.js` `app-shim.js` `mobile-shim.js` | 元の静的版(KV対応のため一部改造) |

## セットアップ(10分ほど)

メニュー名はCloudflareの画面更新で多少変わることがあります。

1. **KV名前空間を作る**
   ダッシュボード → Workers & Pages → **KV** → 「Create a namespace」。名前は何でもOK(例: `obsidian-vault`)。
2. **Pagesプロジェクトを作る**
   Workers & Pages → Create → **Pages** → 「Upload assets」(Direct Upload)→ プロジェクト名を決め、`obsidian-web-kv-pages.zip` をアップロード → Deploy。
3. **バインディングとパスワードを設定する**
   作ったプロジェクト → Settings で、次の2つを **Production** に追加します。
   - **Bindings** → Add → KV namespace → 変数名 `VAULT_KV`、1で作った名前空間を選ぶ
   - **Variables and secrets** → Add → 種類 **Secret** → 名前 `PASSWORD`、値は長めのパスワード(16文字以上を推奨)
   - (任意)Secret `SESSION_SECRET` を足すと、ログインcookieの署名鍵に混ぜます
4. **もう一度デプロイする**
   設定は**次のデプロイから**反映されます。Deployments → 新しいデプロイとして、同じzipをもう一度アップロードしてください。
5. 発行されたURL(`https://〇〇.pages.dev`)を開くとログイン画面が出ます。

うまく動かないとき:
- 画面に `PASSWORD (secret) is not set` → 手順3のSecretが未設定、または手順4の再デプロイを忘れています
- `KV binding VAULT_KV is not configured` → 手順3のバインディング名が `VAULT_KV` でない、または再デプロイ忘れです

## 使い方

各端末で、最初の1回だけ次を行います。

1. URLを開いてログイン(cookieに30日間保存されます)
2. **①** Obsidian本体を読み込む(PC: `obsidian.asar` / スマホ: APKやIPAから取り出した`public`のzip)。端末ごとに1回です
3. **②** 「クラウドvault(KV)を使う」(最初は自動で選ばれます)
4. **③** 開く

2回目以降は「開く」だけです。モバイル版でも、②のクラウドvaultがそのままvaultとして開きます(PC版と同じ階層で、サブフォルダを作る必要はありません)。同じvaultが全端末で共通に見えます。

Obsidian画面の左下に小さく「☁」が出ます。

| 表示 | 意味 |
|---|---|
| ☁ 同期済み | KVに保存済み |
| ☁ 未保存 N | 端末内に保存済み、KVへの送信待ち(Nはファイル数) |
| ☁ オフライン / 同期エラー | 通信できていません。変更は端末内に残り、復帰後に送られます |
| ☁ 書込上限が近いため保留中 | 後述の書き込み節約のため送信を止めています |

クリックすると**今すぐ同期**します。別の端末へ切り替える前に「同期済み」を確認してください。

## 書き込みのまとめ方(無料枠対策)

KV無料枠は**書き込み1日1,000回**(UTC 0時にリセット)です。Obsidianは自動保存で頻繁に書くため、次のようにしています。

- 保存した内容はまず端末内(IndexedDB)に残り、**45秒操作が止まる**か、**最初の変更から3分たつ**とKVへ送ります。同じファイルを何度保存しても、送るのは最後の1回分です
- 作ってすぐ消したファイルや、内容が変わっていない保存は、KVに書きません
- タブを閉じる/隠すときにも送ります。送れなかった分は端末内に残っていて、次に開いたときに送ります
- この端末の本日の書き込みが**400回**を超えると送信間隔を5分〜15分に延ばし、**900回**で自動送信を止めます(☁をクリックすれば送れます)
- ☁にマウスを乗せると、この端末の本日の書き込み回数が見えます(他の端末の分は含みません)

調整したい場合は、ブラウザの開発者ツールで `localStorage` に秒数を入れます: `ow.kv.idle`(既定45)、`ow.kv.max`(既定180)、`ow.kv.limit`(既定900)。

一覧取得(list)にも1日1,000回の別枠があります。開いた時と、画面を触っている間の10分おきに行うだけなので、通常は足ります(30分操作がなければ自動更新を止めます)。

## 制限・注意

- **同じノートを2台で同時に編集しないでください。** 後から送った方が勝ちます(自動マージはしません)。切り替えるときは「同期済み」を確認してから
- 他の端末の変更が見えるまで、最大10分ほどかかります(☁クリックで即時)。KVの仕様上、反映に最大1分ほどの遅れもあります
- 1ファイル25MiBまで(KVの上限)。超える添付は保存できません
- パスの長さは500バイトまで(日本語は1文字3バイトなので、約160文字)
- フォルダの移動・リネームは、中のファイル1つずつが書き込みになります。大きなフォルダを動かすと無料枠を使い切ることがあります
- 全リクエストがWorkerを通るため、Workers無料枠(1日10万リクエスト)に数えられます。個人利用なら十分です
- Obsidian本体を差し替えたり、この版に更新したあとは、ランチャーで本体を**読み込み直して**ください(KV用の読み込みが差し込まれます)

## セキュリティ

- パスワードを知らない人には、ログイン画面以外(コードもvaultも)返しません。vaultはAPIを通してしか読み書きできません
- ログインcookieは `HttpOnly` / `Secure` / `SameSite=Strict`、署名つきで30日有効です。パスワード(Secret)を変えて再デプロイすると、全端末が自動でログアウトします
- パスワード照合は定数時間で行い、失敗すると1秒待たせます。ただし**回数制限はありません**。長いパスワードを使ってください
- 書き込み系APIは、独自ヘッダと送信元の確認でCSRFを防いでいます
- vaultの中身は**暗号化せずに**KVへ保存されます(Cloudflare側の保存時暗号化のみ)。端末間の暗号化(E2E)が必要なら別途改造が必要です
- Obsidian本体はサイトに含まれません。再配布にならないよう、zipやasarをサイトに置かないでください
